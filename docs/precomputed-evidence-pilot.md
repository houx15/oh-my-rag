Hypothesis: source-verified procedure and subsidy records can answer a narrow question family with deterministic selection and exact cited rendering. A graph may improve maintainability/dependency retrieval; it must be compared against equally prepared flat records to avoid attributing preparation benefits to graph storage.

No comparison of these local lookup times against live LLM quality/latency as if workloads were equivalent.

Success: exact required fact IDs, all citations reconstruct from versioned source spans, no unsupported answer, flat/graph parity. Any narrow success only justifies a wider reviewed dataset; it does not beat overall baseline. Report offline ingestion time and online selection/render separately. Keep the original corpus and all prior scores unchanged.

No Jev, embeddings, provider calls or graph database was used; the graph is an explicit next-step mapping in Python. Its subsidy-start/cap relationships are direct fact-ID lookups in both arms. This tests ordered procedure traversal versus a precomputed flat list, not general GraphRAG or learned reasoning.

### Decision and next experiment

Keep the prepared-record approach for broader offline testing; **do not promote a knowledge-graph stack based on this result**. The evidence supports narrow lookup feasibility, not graph superiority, broad performance improvement or replacement of the baseline. Start with ordinary versioned records plus explicit dependency links; graph storage is an implementation choice until relational queries prove its value.

Next, prepare several independent policy families and a source-adjudicated test set containing ambiguous entities, exceptions, temporal changes, absent facts and compound requests. Freeze it before tuning the router. Compare rules, keyword/embedding retrieval and a decision model on the same prepared records, measuring answerable coverage, incorrect automatic answers, required-fact retention and complete-response latency. Jev remains a candidate, not a winner or installed dependency; any new external provider requires the existing authorization/privacy/budget checks. No paid scope is launched by this note.
